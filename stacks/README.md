# stacks — 枚数検知（ラズパイ用・USB配備）

このフォルダだけを USB メモリに入れて、各ラズパイの次の場所へコピーします。

```text
USB の stacks/  →  ラズパイの  ~/Desktop/stacks/
（実パス例: /home/raspai/Desktop/stacks/）
```

開発用の GitHub リポジトリ全体や `tests/` は **USB に入れません**。  
現場へ持っていくのは、この `stacks/` だけです。

**操作はできるだけ GUI（ダブルクリック）で行います。** コマンド入力は不要です。

---

## いちばん簡単な使い方（GUI）

1. USB の `stacks` をデスクトップへコピー → `~/Desktop/stacks`
2. フォルダを開き、**`Stacks制御パネル.desktop`** をダブルクリック  
   - 初回だけ「実行を許可しますか？」「Allow Launching」などと出たら **許可**  
   - もし開けない場合は、同じフォルダの **`control_panel.py`** を右クリック → 「Python で実行」など
3. 開いたウィンドウのボタンだけ使う

| ボタン | いつ押すか |
|--------|------------|
| ① 初回セットアップ | その台で初めて入れるとき／service を更新したとき |
| ② 開始 | 止めたあと、また動かしたいとき |
| ③ 停止 | 検証・差し替えのあいだ一時停止したいとき |
| ④ 状態・ログを見る | 動かない・おかしいとき |
| ⑤ モード切替機能 | 黄ボタンの 3枚/2枚切替を有効／無効にするとき（確認後にプロセス再起動） |

監視の ON/OFF は、この画面ではなく **機械本体のボタン①③** です。  
⑤ は **ラズパイ再起動は不要**で、`stacks.service` だけ再起動します。

## ファイル一覧

| ファイル | 役割 | いつ使うか |
|----------|------|------------|
| `Stacks制御パネル.desktop` | **GUIの入口（推奨）** | ダブルクリックで操作画面を開く |
| `control_panel.py` | 操作画面本体 | `.desktop` から起動される |
| `stacks.py` | 枚数検知プログラム | 常駐実行されるコード（名前は必ずこれ） |
| `mode_switch.conf` | モード切替機能の ON/OFF | ⑤ ボタンが書き換える。手編集も可 |
| `mode_switch_settings.py` | conf 読み書き | 本体・GUI が共有 |
| `stacks.service` | 自動起動の設定 | セットアップがシステムへ登録する |
| `setup.sh` / `start.sh` / `stop.sh` / `show-logs.sh` | 裏方スクリプト | GUI が呼び出す（普段は触らない） |
| `_common.sh` | 共通処理 | 直接使わない |
| `CHECKLIST.md` | 現場確認リスト | 初回設置・改造後の通し確認 |
| `logs/` | 判定CSV | 自動作成 |

## 新しいラズパイへの手順（初回・GUI）

1. USB の `stacks` → `~/Desktop/stacks` へコピー
2. `Stacks制御パネル.desktop` をダブルクリック
3. **① 初回セットアップ** を押す
4. **④ 状態・ログを見る** で `active (running)` を確認
5. 機械の **ボタン①** で監視開始
6. `CHECKLIST.md` を一通り確認

セットアップを何度実行しても、service がいくつも増えることはありません。  
既にある場合は上書き更新して再起動するだけです。

---

## 一時停止・再開（GUI）

| やりたいこと | 操作 |
|--------------|------|
| 今だけ止める | 制御パネル → ③ 停止 |
| また動かす | 制御パネル → ② 開始 |
| 状態・エラーを見る | 制御パネル → ④ ログ |

停止しても「電源入れ直しで自動起動」の設定は残ります。

---

## コードを更新するとき（USB で配る）

1. （開発PC）必要なら `python -m pytest tests/` で通す（リポジトリ側。USB不要）
2. 最新の `stacks_*.py` を **`stacks.py` という名前で複製**し、USB の `stacks/stacks.py` を上書き
3. 各ラズパイで USB から `~/Desktop/stacks` へ上書きコピー
4. 制御パネルを開き:
   - プログラムだけ差し替え → ③ 停止 →（コピー）→ ② 開始  
   - `stacks.service` も変えた → ① セットアップ

現場の実行ファイル名は常に `stacks.py` です。

---

## テスト（pytest）はどこに置く？

| 置き場所 | 方針 |
|----------|------|
| USB の `stacks/` | **入れない** |
| Git リポジトリの `tests/` | **残す**（開発PC・AIエージェント用） |

現場確認は制御パネルの「④ ログ」と `CHECKLIST.md` で行います。

---

## GUI が開かないとき

1. `control_panel.py` を右クリックし、Python3 で実行できないか試す  
2. それでもだめなら、バックアップとしてターミナルで:
   ```bash
   cd ~/Desktop/stacks
   python3 control_panel.py
   ```
3. `.desktop` が「信頼されていない」と出る場合は、右クリックメニューの **Allow Launching / 起動を許可** を選ぶ（Raspberry Pi OS でよくあります）

---

## 複数台へ展開するとき

1. 同じ USB の `stacks/` を各台の `~/Desktop/stacks` にコピー  
2. 各台で制御パネル → ① セットアップ  
3. 台ごとに `CHECKLIST.md` を実施  

ユーザー名が `raspai` 以外の場合は、`stacks.service` と `Stacks制御パネル.desktop` のパス、`stacks.py` の `LOG_DIR` を合わせてください。
